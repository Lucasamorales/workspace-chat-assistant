# Working rules for this repo

## Comments and git
- Never add AI-related metadata anywhere: no "Generated by AI", "Made with Cursor", and no `Co-Authored-By` AI trailers in commits.
- Comments explain the logic and the *why*. Don't state the obvious.
- Commit prefixes:

| Prefix | Usage |
| :--- | :--- |
| `feat:` | New features or functional additions |
| `fix:` | Bug fixes |
| `chore:` | Maintenance, dependency updates, routine tasks |
| `wip:` | Intermediate saves |
| `docs:` | Documentation or comment changes only |
| `devops:` | CI/CD, build scripts, infrastructure |

- Quality gate: use `feat`, `fix` or `devops` only once the change is verified working or explicitly approved. Otherwise `wip:`.

## Terminal
- Default shell is Windows PowerShell 5.1. Never chain with `&&`; use `;` or separate commands.
- Commands run from the repo root. Don't `cd` with absolute paths; use relative paths for subfolders.
- Paths with apostrophes break PowerShell wrappers; use relative paths or proper escaping.
- On a `ParserError` or unterminated-string error: stop, simplify, drop absolute paths, run one step at a time.
- Exception: `infra/*.sh` are bash scripts meant for Google Cloud Shell.

## Project
- Module isolation rules and layout: `README.md`. Run `npm test` before any commit that claims `feat`/`fix`/`devops`.
